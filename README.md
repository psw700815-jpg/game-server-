# game-server-
# 🎮 로컬 협동 탑다운 슈터

2~4명의 플레이어가 함께 적의 공격을 막아내는 **로컬 협동(Co-op) 탑다운 슈팅 게임**입니다.  
동료 부활, 자원 공유, 역할 분담을 통해 혼자보다 함께할 때 더 강해지는 플레이를 목표로 합니다.

## 📌 핵심 컨셉

| 항목 | 내용 |
| --- | --- |
| 장르 | 탑다운 슈팅 |
| 플레이 인원 | 2~4명 |
| 플레이 방식 | 로컬 협동 플레이(Co-op) |
| 핵심 요소 | 웨이브 생존, 기지 방어, 팀워크 |

## 🎯 공유 목표

플레이어들은 팀을 이루어 공통의 목표를 달성합니다.

- **웨이브 생존:** 끊임없이 몰려오는 적을 함께 막아내며 생존합니다.
- **코어 및 기지 방어:** 적의 공격으로부터 팀의 공용 코어 또는 기지를 지킵니다.

## 🤝 주요 협동 시스템

### 1. 동료 부활

쓰러진 동료 근처로 이동하여 부활시킬 수 있습니다.  
적을 상대하는 동시에 동료를 구해야 하므로 팀원 간의 협력이 중요합니다.

### 2. 협동 콤보 보너스

여러 플레이어가 같은 적을 함께 공격하여 처치하면 추가 점수 또는 아이템 드롭 보너스를 획득합니다.  
팀원들이 공격 대상을 맞추고 협력하도록 유도합니다.

### 3. 자원 공유

획득한 파워업을 혼자 사용할지, 팀 전체에 나눌지 선택할 수 있습니다.  
개인의 전투력 강화와 팀 전체의 생존 사이에서 전략적인 판단이 필요합니다.

| 파워업 | 효과 |
| --- | --- |
| `MultiShot` | 다중 발사 |
| `Shield` | 보호막 |
| `Heal` | 체력 회복 |

### 4. 캐릭터별 역할 분화

캐릭터마다 다른 무기와 스킬을 사용하여 팀 내 역할을 나눕니다.

| 역할 | 주요 특징 |
| --- | --- |
| 탱커형 | 적의 공격을 받아내며 동료를 보호 |
| 딜러형 | 높은 공격력으로 적을 빠르게 처치 |
| 힐러형 | 체력 회복과 지원으로 팀의 생존 유지 |

## 🌐 게임 서버의 주요 역할

게임에서 발생하는 상황과 각 상황에서 서버가 처리해야 할 작업을 정리한 표입니다.

| 게임에서 벌어지는 일 | 서버가 해야 할 일 |
| --- | --- |
| 🎮 **게임을 켰다** | 서버 접속 요청 수신 → 사용자 인증(누구인지 확인) → 방/세션 목록 응답 |
| 👥 **친구랑 같이 하고 싶다** | 방(룸) 생성 및 입장 처리 → 참가자 목록 관리 → 같은 방의 모든 플레이어에게 입장 사실 알림(브로드캐스트) |
| 🏃 **캐릭터를 움직였다** | 클라이언트가 보낸 입력(방향키 등) 수신 → 이동 가능 여부 검증(벽 뚫기 등 방지) → 새 좌표 계산 → 같은 세션의 다른 클라이언트에게 좌표 전송 |
| 🎁 **아이템을 먹었다** | 클라이언트의 아이템 획득 요청 수신 → 해당 위치에 아이템이 있는지 및 획득 가능한지 검증 → 획득 처리 → 모든 참가자에게 아이템 제거 알림 → 인벤토리/점수 갱신 |
| 🏁 **게임이 끝났다** | 승패 및 점수 판정 → 모든 참가자에게 결과 전송 → 세션 종료 및 리소스 정리(방 삭제 등) |
| 🔄 **다시 접속했다** | 사용자 재인증 → 기존 세션 및 참가 정보 확인 → 복귀 가능한 경우 세션 재연결 및 현재 게임 상태 동기화 → 복귀할 수 없는 경우 로비로 안내 |

> **참고:** 재접속 처리 흐름은 예시이며, 프로젝트의 재접속 정책에 맞게 조정할 예정입니다.

## 📡 패킷 정의

본 게임은 클라이언트와 서버가 주고받는 패킷을 **총 16종**으로 설계합니다.

| 구분 | 전송 방향 | 개수 | 주요 역할 |
| --- | --- | --- | --- |
| **C2S** | 클라이언트 → 서버 | 8종 | 로그인, 방 관리, 플레이어 행동 요청 |
| **S2C** | 서버 → 클라이언트 | 8종 | 요청 처리 결과, 게임 상태, 발생한 사건 전달 |

> **C2S**는 Client to Server, **S2C**는 Server to Client를 의미합니다.  
> 클라이언트는 행동을 요청하고, 서버는 요청을 검증·처리한 뒤 확정된 결과와 게임 상태를 전달합니다.

### 📤 클라이언트 → 서버 패킷

플레이어의 입력과 요청을 서버에 전달하는 패킷입니다.

| 번호 | 패킷 이름 | 기능 | 주요 데이터 | 서버 검증 및 처리 |
| --- | --- | --- | --- | --- |
| 1 | `C2S_LOGIN_REQUEST` | **로그인 요청** | 로그인 아이디, 비밀번호 | 계정 정보를 검증하고, 성공하면 해당 연결을 로그인한 사용자와 연결합니다. |
| 2 | `C2S_ROOM_REQUEST` | **방 관리 요청** | 요청 번호, 요청 종류, 방 번호, 선택 역할, 준비 여부 | 로그인 여부, 방 존재 여부, 정원, 참가 상태, 게임 시작 권한과 조건을 확인한 뒤 방 관련 요청을 처리합니다. |
| 3 | `C2S_MOVE_REQUEST` | **이동 요청** | 입력 순번, 이동 방향 | 이동 가능한 상태인지 확인하고, 이동 속도와 벽 충돌을 적용하여 실제 위치를 계산합니다. |
| 4 | `C2S_ATTACK_REQUEST` | **일반 공격 요청** | 요청 번호, 무기 번호, 조준 방향 | 무기 보유 여부, 탄약, 공격 간격, 공격 가능한 상태를 확인하고 투사체 생성이나 명중·피해를 처리합니다. |
| 5 | `C2S_SKILL_REQUEST` | **스킬 사용 요청** | 요청 번호, 스킬 번호, 대상 또는 사용 방향 | 해당 캐릭터가 가진 스킬인지, 재사용 대기시간과 사용 자원, 대상 조건이 맞는지 확인한 뒤 효과를 적용합니다. |
| 6 | `C2S_ITEM_PICKUP_REQUEST` | **아이템 획득 요청** | 요청 번호, 아이템 번호 | 아이템의 존재 여부, 올바른 대상인지, 획득 거리 안인지, 이미 획득된 아이템인지 등을 검증한 뒤 획득을 처리합니다. |
| 7 | `C2S_ITEM_USE_REQUEST` | **아이템 사용·공유 요청** | 요청 번호, 보유 아이템 번호, 사용 방식(`SELF` / `TEAM`) | 아이템 보유 여부, 현재 사용 가능 여부, 팀 공유 가능 여부와 적용 대상을 검증한 뒤 아이템을 소모하고 효과를 적용합니다. |
| 8 | `C2S_REVIVE_REQUEST` | **동료 부활 요청** | 요청 번호, 대상 플레이어 번호, 요청 종류(`START` / `CANCEL`) | 대상의 존재 여부, 같은 팀인지, 쓰러진 상태인지, 요청자가 부활 가능한 상태인지, 거리가 적절한지 검증합니다. 필요한 시간 동안 조건이 유지되면 부활을 완료합니다. |

#### 방 관리 요청 종류

`C2S_ROOM_REQUEST`는 요청 종류에 따라 다음 기능을 구분합니다.

| 요청 종류 | 기능 |
| --- | --- |
| `LIST_ROOMS` | 입장 가능한 방 목록 조회 |
| `CREATE_ROOM` | 새로운 방 생성 |
| `JOIN_ROOM` | 지정한 방에 입장 |
| `LEAVE_ROOM` | 현재 방에서 퇴장 |
| `SELECT_ROLE` | 탱커·딜러·힐러 등 캐릭터 역할 선택 |
| `SET_READY` | 준비 상태 변경 |
| `START_GAME` | 게임 시작 요청 |

> 모든 요청에 모든 데이터를 넣는 것은 아닙니다.  
> 예를 들어 방 입장에는 방 번호를, 역할 선택에는 선택한 역할을 전달합니다.

#### 아이템 사용 및 부활 요청 구분

| 패킷 | 구분 값 | 의미 |
| --- | --- | --- |
| `C2S_ITEM_USE_REQUEST` | `SELF` | 보유한 파워업을 자신에게 사용 |
| `C2S_ITEM_USE_REQUEST` | `TEAM` | 보유한 파워업을 팀에 공유하여 사용 |
| `C2S_REVIVE_REQUEST` | `START` | 대상 동료의 부활 시작 요청 |
| `C2S_REVIVE_REQUEST` | `CANCEL` | 진행 중인 부활 취소 요청 |

### 📥 서버 → 클라이언트 패킷

서버가 검증·처리한 결과와 현재 게임 상태를 클라이언트에 전달하는 패킷입니다.

| 번호 | 패킷 이름 | 기능 | 주요 데이터 | 전송 대상 |
| --- | --- | --- | --- | --- |
| 1 | `S2C_LOGIN_RESULT` | **로그인 결과 전달** | 성공·실패 코드, 성공 시 사용자 번호와 닉네임 | 로그인을 요청한 클라이언트 |
| 2 | `S2C_ROOM_UPDATE` | **방 정보·처리 결과 전달** | 요청 번호, 결과 코드, 방 목록 또는 방 정보, 참가자 목록, 역할, 준비 상태, 게임 시작 여부 | 요청 결과는 요청자, 방 상태 변경은 같은 방의 모든 클라이언트 |
| 3 | `S2C_WORLD_STATE` | **게임 상태 동기화** | 서버 갱신 순번, 플레이어·적·투사체·아이템 상태, 코어 체력, 현재 웨이브 | 같은 방의 모든 클라이언트 |
| 4 | `S2C_COMBAT_EVENT` | **전투 사건·처리 결과 알림** | 사건 종류, 행동한 플레이어, 대상, 공격·스킬 종류, 피해·회복량, 콤보 보상, 결과 코드 | 공유할 전투 사건은 같은 방 전체, 요청 실패는 요청자 |
| 5 | `S2C_ITEM_PICKUP_RESULT` | **아이템 획득 결과 전달** | 요청 번호, 결과 코드, 아이템 번호, 획득한 플레이어 번호 | 획득 성공은 같은 방 전체, 실패는 요청자 |
| 6 | `S2C_ITEM_USE_RESULT` | **아이템 사용·공유 결과 전달** | 요청 번호, 결과 코드, 아이템 종류, 개인·팀 사용 구분, 적용 대상, 효과 정보 | 사용 성공은 같은 방 전체, 실패는 요청자 |
| 7 | `S2C_REVIVE_EVENT` | **부활 진행·결과 알림** | 부활 단계, 요청자와 대상 번호, 남은 시간, 완료 시 체력, 결과 코드 | 부활 상태 변경은 같은 방 전체, 요청 실패는 요청자 |
| 8 | `S2C_GAME_RESULT` | **게임 종료 결과 전달** | 승패, 종료 사유, 최종 점수, 도달 웨이브, 생존 시간 | 같은 방의 모든 클라이언트 |

#### 게임 상태와 사건 알림의 차이

| 구분 | 관련 패킷 | 전달 내용 예시 | 클라이언트 처리 |
| --- | --- | --- | --- |
| **현재 상태** | `S2C_WORLD_STATE` | 플레이어의 위치, 현재 체력, 코어 체력 | 서버에서 받은 상태를 화면에 반영 |
| **발생한 사건** | `S2C_COMBAT_EVENT`, `S2C_REVIVE_EVENT` 등 | 공격 명중, 협동 콤보 발생, 동료 부활 완료 | 해당 사건의 효과음, 이펙트, 알림 표시 |

> 사건 처리로 변경된 체력·위치·아이템 등의 정보는 이후 `S2C_WORLD_STATE`에도 반영합니다.

### 🔄 주요 요청과 서버 응답 관계

클라이언트 요청 하나에 서버 패킷 하나만 대응하는 것은 아닙니다.  
서버는 요청 처리 결과를 알리는 동시에, 변경된 게임 상태도 별도로 전달할 수 있습니다.

| 클라이언트 요청 | 서버 검증·처리 | 서버가 전달하는 패킷 |
| --- | --- | --- |
| `C2S_LOGIN_REQUEST` | 계정 정보 검증 및 로그인 처리 | `S2C_LOGIN_RESULT` |
| `C2S_ROOM_REQUEST` | 요청 종류에 맞는 방 관리 처리 | `S2C_ROOM_UPDATE` |
| `C2S_MOVE_REQUEST` | 이동 가능 여부 확인 및 위치 계산 | `S2C_WORLD_STATE` |
| `C2S_ATTACK_REQUEST` | 공격 조건 확인 및 공격 처리 | `S2C_COMBAT_EVENT`, `S2C_WORLD_STATE` |
| `C2S_SKILL_REQUEST` | 스킬 사용 조건 확인 및 효과 적용 | `S2C_COMBAT_EVENT`, `S2C_WORLD_STATE` |
| `C2S_ITEM_PICKUP_REQUEST` | 대상·존재 여부·거리·획득 가능 여부 확인 | `S2C_ITEM_PICKUP_RESULT`, `S2C_WORLD_STATE` |
| `C2S_ITEM_USE_REQUEST` | 보유·사용·공유 가능 여부 확인 및 효과 적용 | `S2C_ITEM_USE_RESULT`, `S2C_WORLD_STATE` |
| `C2S_REVIVE_REQUEST` | 대상·거리·부활 가능 상태 확인 및 부활 처리 | `S2C_REVIVE_EVENT`, `S2C_WORLD_STATE` |

> `S2C_GAME_RESULT`는 클라이언트의 별도 종료 요청이 아니라, 서버가 게임 종료 조건을 판단한 뒤 참가자들에게 전송합니다.

### 🛡️ 서버 처리 원칙

- **서버 판정:** 클라이언트가 보낸 위치·피해량 등의 결과를 그대로 신뢰하지 않고, 서버가 입력과 게임 규칙을 기준으로 최종 상태를 결정합니다.
- **요청 검증:** 행동을 처리하기 전에 대상의 존재 여부, 거리, 현재 상태, 사용 권한과 조건을 확인합니다.
- **전송 대상 구분:** 로그인 결과와 개별 요청 실패는 요청자에게, 함께 확인해야 하는 게임 상태와 사건은 같은 방의 참가자들에게 전달합니다.
- **상태 반영:** 요청 처리로 변경된 정보는 서버의 게임 상태에 반영하고, 상태 동기화 패킷을 통해 클라이언트에 전달합니다.
